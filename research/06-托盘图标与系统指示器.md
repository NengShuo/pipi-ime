# 06 · 托盘那两个图标到底是什么

## 一、现象

任务栏右下角同时出现两个输入法相关图标：

1. 白底黄框的字母 P（我们做的）
2. 黑底白色符号的方块，悬停显示「小狼毫 中文简体 中国」
3. 左键点击第 2 个，弹出系统输入法列表（微软拼音、语言首选项）

用户疑问：能不能只留皮皮一个？以后上架会不会露馅？

## 二、决定性实验

停掉 `WeaselServer.exe`，再重启 `explorer.exe`（清掉托盘幽灵图标缓存），观察：

| 状态 | 托盘表现 |
|---|---|
| 服务运行中 | 黄 P + 黑底符号方块 |
| 服务停止后 | 黄 P 消失，黑底方块变成**灰白「中」字** |

结论：

- **黄 P** = `WeaselServer.exe` 自己创建的托盘图标，图标来自配置 `schema/icon`，
  完全由我们控制。
- **黑底方块 / 灰白「中」** = **Windows 系统的输入法指示器**（Input Indicator），
  不是任何输入法的进程画的。

为什么停服务后变成「中」？因为系统回落到微软拼音（`ChsIME.exe`），
指示器就换成微软拼音的图标。这说明它显示的是「当前激活的那个输入法」。

## 三、名字和图标的来源

```
HKLM\SOFTWARE\Microsoft\CTF\TIP\{A3F4CDED-B1E9-41EE-9CA6-7B4D0DE6CB0A}
  \LanguageProfile\0x00000804\{3D02CAB6-2B8E-4781-BA20-1C9267529467}
    Description = 小狼毫          ← 悬停和列表里显示的名字
    IconFile    = C:\Windows\system32\weasel.dll
    IconIndex   = 0
```

`weasel.dll` 里有 4 个图标：

| index | 外观 | 用途 |
|---|---|---|
| 0 | 黑底白色符号 | 默认/指示器用 |
| 1 | 红框 A | 英文模式 |
| 2 | 灰框 中 | 中文模式 |
| 3 | 绿框 | 全角/其他 |

用户之前抱怨的「红方块 A / 蓝方块 中」就是 idx 1 和 idx 2。

## 四、为什么 HKCU 覆盖无效

试过在 `HKCU\Software\Microsoft\CTF\TIP\...` 建同结构分支覆盖，
写完重启 explorer 无任何变化 → **CTF 只读 HKLM，不认用户级覆盖**。

`HKCU\...\Explorer\Advanced\ShowInputIndicator = 0` 和
`HKCU\...\CTF\LangBar\ShowStatus = 4` 也试过，重启 explorer 后指示器仍在，
说明 Win11 下这两个键不足以隐藏输入指示器。

## 五、解决方案（三步，缺一不可）

### 1. 改 HKLM 的名字和图标（需管理员，一次性）

脚本 `tools/fix_ime_name.ps1`，通过 `tools/改输入法名字.bat` 提权运行：

- `Description` → 皮皮输入法
- `IconFile` → `%APPDATA%\Rime\pipi-p.ico`
- `IconIndex` → 0

注意：脚本必须**纯 ASCII**，中文名用 Unicode 码点拼
（`[char]0x76AE + ...`），否则 PowerShell 5.1 读无 BOM 文件会乱码。
脚本内层路径用**反斜杠**，正斜杠虽然也能工作但曾经写出过异常文件。

### 2. 关掉小狼毫自己的托盘图标

`weasel.custom.yaml` 加 `"style/display_tray_icon": false`，
这样只剩系统指示器一个图标。

**顺序很重要**：必须先做第 1 步。否则关掉自己的托盘后，
剩下的就是写着「小狼毫」的方块，比原来更糟。

### 3. （可选）移除微软拼音

```powershell
$l = Get-WinUserLanguageList
$l[0].InputMethodTips.Remove("0804:{81D4E9C9-...}{FA550B04-...}")
Set-WinUserLanguageList $l -Force
```

移除后点击指示器弹出的列表里只有皮皮一项。
**原型阶段不建议做**：万一皮皮出问题，用户没有备用输入法可打字。

## 六、点击弹出输入法列表正常吗

正常。这是 Windows 自己的输入法切换菜单，搜狗、微软拼音、QQ 输入法
点了都是同一个菜单。这不是露馅，是系统标准行为。

## 七、上架 / 商业化的硬约束（重点）

| 组件 | 许可证 | 能否闭源商用 |
|---|---|---|
| Weasel（小狼毫前端） | **GPL-3.0** | ❌ 分发修改版必须开源整个前端 |
| librime（引擎） | **BSD-3-Clause** | ✅ 可以，保留版权声明即可 |

也就是说：

- **现在这套东西不能直接拿去上架卖。** 它是对 GPL 程序的修改 +
  重新配置，一旦对外分发二进制，法律上有义务提供完整前端源码。
- 正确路线：**自研前端 + librime 引擎**。
  - Windows：自己写 TSF 文本服务 DLL（实现 `ITfTextInputProcessor` 等）
    + 自绘候选窗，静态链接 librime
  - Android：自己写 `InputMethodService`，用 JNI 调 librime
  - iOS：Keyboard Extension + librime（librime 有 iOS 构建）
- librime 只负责「拼音串 → 候选词」，UI、状态栏、候选窗、安装包、
  设置面板全部要自己写。

所以现阶段这套东西的正确定位是：**交互和算法的验证原型**，
不是可发布的产品。验证结论（去模式化、自动中英识别、拼音备选）
可以直接搬到自研前端里。

## 八、遗留

- `C:\Windows\system32\weasel.dll`（1090048 字节）与安装目录的
  （909312 字节）不一致，system32 那份是旧版残留。
  改 `IconFile` 后就不再依赖它，但仍是隐患。
- `IconFile` 指向 `%APPDATA%` 下的 ico，用户误删会导致图标丢失。
  正式产品应放进安装目录，并在卸载时清理。
