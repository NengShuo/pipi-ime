# 05 · 候选顺序调整与外观重做

> 触发：用户试用后提了三个意见——第二列拼音不能选等于没用、候选窗白底黑框难看、
> 「原样拼音」要提到第 2 位。

## 一、取消第二列拼音注释

**用户的原话**：「第二列参考你也没法选它呀……除非那个拼音我能点可以选它，
要是不能选的话那拼音就不用出现。」

技术事实：候选右侧的 comment 是纯渲染字段，Rime 候选窗不支持点击、也没有
「选中 comment」这个动作。选中第 N 项上屏的永远是候选正文（中文），
comment 只是装饰。所以这一列对「想把字母原样打出去」毫无帮助，还把窗撑宽了。

**处理**：关掉 `translator/spelling_hints` 和 `translator/always_show_comments`
（这两个键是让 script_translator 把拼写写进 comment 的开关），
`pipi_filter` 里构造 Candidate 时 comment 传空串。

## 二、「原样拼音」提到第 2 位

原来的实现是插在第 5 位（第一页末位），理由是「不用翻页」。
用户明确要求提到第 2 位：第 1 位中文、第 2 位拼音、其余往后排。

`rime.lua::pipi_filter` 现在的顺序逻辑：

```lua
local n = 0
for cand in input:iter() do
  yield(cand)          -- 第 1 位：中文主候选
  n = n + 1
  if fallback and n == 1 then
    yield(fallback)    -- 第 2 位：原样拼音，可选中
  end
end
```

注意 yield 顺序是「先 yield 中文，计数到 1 再 yield 拼音」，
这样拼音稳定落在第 2 位，不受候选总数影响，也不再需要读 `menu/page_size`。

实测（引擎直驱）：`woyaochifan` → 1 我要吃饭 / 2 woyaochifan / 3 我要吃 / 4 我要 / 5 我呀。
按 2 上屏 `woyaochifan`，验证通过。

英文分支不变：1 meeting（空格即上屏）/ 2 么额听 / 3 么。

## 三、外观重做

### 坑 1：真正的布局参数在 `style/layout/` 下面

Weasel 0.17 的 `style/xxx` 只是兜底，实际生效的是 `style/layout/xxx`。
之前只改顶层 `style/margin_x` 等，全被 layout 里的默认值压住了
（默认 `border_width: 3` + `border_color` 没配 → 就是用户看到的「白底黑粗框」）。

正确写法：

```yaml
"style/layout/border_width": 0
"style/layout/hilite_padding": 6
"style/layout/round_corner": 8
...
```

### 坑 2：高亮底色必须用 `0x00BBGGRR`，alpha 填 FF 就不画

这是本轮最隐蔽的坑。`hilited_candidate_back_color: 0xFFC0E0FF` 加进去，
颜色怎么调都看不见高亮块，一度怀疑是 padding 太小、选中项没落到第 0 项
（用 ctypes 读 `menu.highlighted_candidate_index` 确认是 0，排除）。

改成 `0x00C0E0FF` 立刻出现。

结论：Weasel 对「填充块」类颜色（hilited_candidate_back_color）的 alpha 位有语义，
**0 = 正常绘制，FF = 不绘制**。而 `back_color`、`text_color` 这类 alpha 位填 FF 是正常的。
两套规则混在一起，只能记住：**高亮底一律写 0x00**。
