# 07 · 开源发布方案

> 目标：让别人从 GitHub 拿到皮皮，30 秒装好，右下角只有一个皮皮角标。

## 一、先回答三个问题

### Q1：别人下载能直接用吗？

**能，但有一个前提：对方机器上要先有小狼毫。**

皮皮不是独立程序，是 Rime/Weasel 的配置层。引擎（拼音→汉字的翻译、词库、候选生成）全在小狼毫里，皮皮只负责"怎么判断中英"和"候选怎么排"。

所以安装流程是两步：

1. 装小狼毫（官方安装包，一次）
2. 装皮皮（我们的脚本，一次）

安装脚本会自动检测第一步做没做，没做就提示并打开下载页。

### Q2：别人用时也会看到两个角标吗？

**走我们的安装器就不会。**

默认装小狼毫确实会出现两个图标，因为它们是两个完全不同的东西：

| 图标 | 是谁画的 | 名字来源 |
|---|---|---|
| 小狼毫自己的托盘图标 | WeaselServer 进程 | `schema/icon` 配置 |
| 系统的输入法指示器 | Windows explorer | `HKLM\...\CTF\TIP\...\Description` |

`install.ps1` 做了两件事把它们合成一个：

1. **改 HKLM 注册表**：`Description` → 「皮皮输入法」，`IconFile` → `pipi-p.ico`，`IconIndex` → 0
2. **关掉小狼毫自带托盘**：`style/display_tray_icon: false`

剩下的那个是系统指示器，但它已经叫皮皮、图标也是皮皮了。

### Q3：能只留一个吗？

**能，代价是失去小狼毫的右键菜单**（重新部署 / 方案选单 / 用户文件夹）。

补偿：发行包里带 `皮皮维护.bat`，把这三个功能做成了菜单。

```
│   │   ├── install.bat
│   │   ├── install.ps1
│   │   ├── uninstall.bat
│   │   ├── uninstall.ps1
│   │   ├── 皮皮维护.bat
│   │   ├── 使用说明.txt
│   │   └── files/                ← 和 config/ 内容一致
│   └── 皮皮输入法-v0.1.zip        ← Release 附件
├── assets/
│   ├── preview-candidate.png     ← README 里的效果图
│   ├── preview-icon.png
│   └── pipi-p.ico 等
├── research/                     ← 技术验证记录（1-7 篇）
└── tools/                        ← 开发调试脚本（别人不一定能跑，无所谓）
```

**为什么要有 `config/` 和 `dist/.../files/` 两份相同的文件？**

- `config/` 给在线安装用，路径必须全 ASCII，否则 URL 编码容易出错
- `files/` 给离线 zip 用，跟着安装脚本走

改配置时两边都要改。或者在仓库根加个 `make_dist.py` 同步，目前是手工复制。

## 三、发布步骤

### 1. 建仓库

在 GitHub 上 New repository，名字 `pipi-ime`，Public，**不要**勾选自动生成 README（会和本地的冲突）。

### 2. 推代码

```bash
cd "D:/Work Buddy/DM/2026-11-01-12-30-15/pipi-ime"
git init
git add .
git commit -m "皮皮输入法 v0.1：自动识别中英的拼音输入法"
git branch -M main
git remote add origin https://github.com/<你的用户名>/pipi-ime.git
git push -u origin main
```

注意 `.gitignore` 已经排除了 `setup/*.exe`（12MB 的官方安装包）和调试截图。

### 3. 改两处占位符

- `install-online.ps1` 第 10 行：`$Repo = "pipi-ime/pipi-ime"` → 改成 `你的用户名/pipi-ime`
- `README.md` 里那行 `irm` 命令里的 `YOURNAME`

改完重推一次。

### 4. 发 Release

Releases → Draft a new release：

- Tag：`v0.1`
- 标题：`皮皮输入法 v0.1`
- 说明：贴 README 的功能介绍
- 附件：上传 `dist/皮皮输入法-v0.1.zip`（78 KB）

### 5. 验证

用无痕窗口 / 另一台机器走一遍：

```powershell
# 管理员终端
irm https://raw.githubusercontent.com/<用户名>/pipi-ime/main/install-online.ps1 | iex
```

## 四、安装器做了什么

`install.ps1` 的完整流程（242 行）：

| 步骤 | 动作 | 失败时 |
|---|---|---|
| 0 | 检查管理员权限 | 提示重开 |
| 1 | 递归找 `WeaselServer.exe` | 提示装小狼毫 + 打开下载页 |
| 2 | 复制 5 个配置到 `%APPDATA%\Rime`，同名文件先备份 | 报错退出 |
| 3 | 遍历 HKLM 找 `IconFile` 含 `weasel.dll` 的项，改名换图标 | 警告，不中断 |
| 4 | `WeaselDeployer.exe /deploy`，比对 `build/weasel.yaml` 时间戳确认编译 | 提示手动部署 |
| 5 | 把 `build/weasel.yaml` 里 `display_tray_icon` 改成 false（无 BOM 写回） | 警告 |
| 6 | 重启 WeaselServer | 提示手动启动 |
| 7 | 重启 explorer 刷新托盘 | 自动拉起 |

### 几个踩过的坑（写进脚本里了）

1. **注册表项不是只有一处**。这台机器实测有 **10 处** `IconFile` 指向 `weasel.dll`（每个语言/键盘布局一份）。只改一处不生效，必须 `Get-ChildItem -Recurse` 遍历。
2. **用户级注册表覆盖无效**。`HKCU\Software\Microsoft\CTF\TIP\...` 建同结构，CTF 不读。
3. **`Set-Content -Encoding UTF8` 会写 BOM**，而 Rime 的 YAML 解析器不认 BOM。必须用 `[System.IO.File]::WriteAllText` + `UTF8Encoding($false)`。
4. **`Start-Process` 拉起的 WeaselServer 会随父进程回收**。安装器是用户手动双击的独立进程，没这个问题；但在 agent 会话里跑就会掉。
5. **PS 5.1 读无 BOM 的 UTF-8 脚本会乱码**，所以 `.ps1` 必须存成 UTF-8 **with** BOM，`.bat` 用 `chcp 65001` + 无 BOM。

## 五、合规

| 组件 | 许可 | 我们的处理 |
|---|---|---|
| Rime/Weasel 前端 | GPL-3.0 | 不打包二进制，让用户自己从官方下；我们的配置同样以 GPL-3.0 发布 |
| librime 引擎 | BSD-3-Clause | 随小狼毫分发，无需额外处理 |
| 雾凇拼音词库 | GPL-3.0 | 用户装小狼毫时自己选的方案，我们不分发 |
| 皮皮自己的代码 | GPL-3.0 | LICENSE 放全文 |

**结论：开源分发完全合法。**

不能做的是：把这个包闭源卖。因为它是 GPL 程序的衍生配置，分发二进制就触发开源源码义务。

商业版路线见 `06-托盘图标与系统指示器.md` 末尾：自研 TSF 前端（参考 MIT 许可的 SampleIME）+ librime（BSD）+ 自建词库。

### 两个图标的判定方法（重要）

想确认"哪个图标是谁"，做这个实验：

```powershell
Stop-Process -Name WeaselServer -Force      # 停服务
Stop-Process -Name explorer -Force           # 清托盘缓存
Start-Process explorer.exe
# 截图看还剩几个
```

结果解读：
- 停服务后**变成「中」的那个 = 系统指示器**（回落到微软拼音）
- **仍然保持原样的那个 = Weasel 托盘**（缓存没清掉而已）

这台机器的实测结论：**系统指示器在左，Weasel 托盘在最右（贴着时钟）**。

### `display_tray_icon: false` 为什么无效

读 Weasel 源码（`WeaselServer/WeaselTrayIcon.cpp`）：

```cpp
BOOL WeaselTrayIcon::Create(HWND hTargetWnd) {
  ...
  CSystemTray::Create(...);        // 先无条件建出来
  if (!m_style.display_tray_icon) RemoveIcon();
  else AddIcon();
}

void WeaselTrayIcon::Refresh(const WeaselTrayIconState& state) {
  if (!state.display_tray_icon && !state.disabled) {
    if (m_mode != INITIAL) { RemoveIcon(); m_mode = INITIAL; }   // ← 初次 m_mode 就是 INITIAL
    return;
  }
  ...
}
```

两个问题叠加：
1. `Create()` 时 `m_style` 可能还没从配置加载完，读到默认值 `true` → 建出了图标
2. 之后 `Refresh()` 读到 `false`，但 `m_mode == INITIAL`，**不执行 RemoveIcon**

结论：这是上游 bug，不是我们配错。已用引擎 API 交叉验证过配置确实读到了 `0`：

```
RimeConfigOpen('weasel') -> 1 (ok)
  style/display_tray_icon = 0
  style/color_scheme      = 'pipi'
```

### 最终方案：透明图标

`config/pipi-blank.ico`（8 档尺寸，全透明，1.1 KB），配到方案里：

```yaml
"schema/icon": "pipi-blank.ico"
"schema/ascii_icon": "pipi-blank.ico"
```

效果：小狼毫的托盘图标仍占 16px，但不可见；系统指示器正常显示皮皮 P。
代价：托盘区多一个看不见的空位（约 16px），肉眼几乎察觉不到。
